# Guide format

How a companion guide is laid out so the PDF pipeline can build it
([ADR 0016](decisions/0016-guide-format-and-generic-pdf-pipeline.md)). Read
this when writing a guide or importing one. How the pipeline works is in
[`architecture.md`](architecture.md#pdf-pipeline); the commands are in
[`development.md`](development.md#make).

## A guide is a folder

Every folder in `src/content/` with a `metadata.yml` is a guide. Adding one
needs nothing else: no list to edit, no script to change.

```
src/content/<guide>/
  metadata.yml           title, author, ... (below)
  00-intro.md            chapter 1: the introduction
  02-heuristics.md       chapter 2
  03-part-1-....md
  ...
```

- **Chapters** are the files named `[0-9][0-9]-*.md`, in name order. Gaps in
  the numbers are allowed. Other files in the folder are not part of the PDF.
- **The PDF** is `public/<guide>.pdf`, named after the folder. It is
  committed; the pre-commit hook rebuilds it
  ([`development.md`](development.md#the-pdf-hook)).

## `metadata.yml`

```yaml
title: Harness Engineering
subtitle: A Practical Guide
author: Javier Sandino
coauthor: Claude Sonnet 4.6
date: 2026-09-07
```

| Field | Required | Used for |
|---|---|---|
| `title` | yes | Cover; the PDF's `/Title` |
| `subtitle` | no | Cover; appended to `/Title` as `<title> - <subtitle>` |
| `author` | yes | Cover; the PDF's `/Author` |
| `coauthor` | no | Cover line `Co-authored with <coauthor>`, left out when unset |
| `date` | no | Cover line `Last modified: <date>`, written `YYYY-MM-DD` |

**The date.** Leave `date` out to use the date of the guide's last change:
today if its folder has staged or uncommitted changes, otherwise the date of
the last commit that touched the folder. Set it only to pin the cover to a
fixed day. The build prints which date it used and why.

## What the pipeline adds

A guide contains none of these; the pipeline adds them to every guide:

- **Cover:** one shared template (`scripts/pdf/cover.tex`), filled from
  `metadata.yml`.
- **Page breaks:** every chapter starts on a new page.
- **Contents:** generated by LaTeX, with page numbers, on a new page after
  the first chapter.

## Headings

The contents lists headings by these rules
(`scripts/pdf/contents-filter.mjs`):

| Heading | In the contents? |
|---|---|
| Anything in the first chapter | No |
| `#` (a chapter, part or appendix title) | Yes |
| `## 3. A main section` (first word a number and a full stop) | Yes |
| `## A.2 An appendix section` | No |
| `## What's next` (not numbered) | No |
| `###` and deeper | No |

So number main sections `1.`, `2.`, … across the guide, appendix sections
`A.1`, `A.2`, …, and leave bridging or grouping headings unnumbered.
Headings left out of the contents are also left out of the PDF's bookmarks.

## Named blocks

Layout effects use named blocks, never raw LaTeX
([ADR 0016](decisions/0016-guide-format-and-generic-pdf-pipeline.md)):

| Block | Effect in the PDF |
|---|---|
| `::: spread` … `:::` | Spaces its blocks evenly down the rest of the page (`scripts/pdf/spread-filter.mjs`) |

```markdown
::: spread
**1. First idea** — …

**2. Second idea** — …
:::
```

Outside the PDF, a named block's contents simply follow one another.

## Diagram colours

Diagrams colour nodes by name, never by value
([ADR 0016](decisions/0016-guide-format-and-generic-pdf-pipeline.md)):
`class A,B sky`, not `style` or `fill:`. The pipeline defines each name in
every diagram (`scripts/pdf/diagram-classes.mmd`); in print:

| Name | Fill | Stroke |
|---|---|---|
| `sky` | `#e8f0ff` | `#36c` |
| `violet` | `#f0e8ff` | `#93c` |
| `emerald` | `#e8ffe8` | `#3a3` |
| `coral` | `#ffe8e8` | `#c33` |
| `amber` | `#fff4e8` | `#c63` |
| `neutral` | `#f4f4f4` | `#888` |

Text is black on every colour.

## Content rules

`scripts/pdf/content-check.mjs` rejects, in every chapter:

- **Raw LaTeX:** a `{=latex}` or `{=tex}` block or inline span. Use a
  [named block](#named-blocks) or plain Markdown. (LaTeX shown inside
  another code block is fine.)
- **Diagram styling:** a `style`, `linkStyle` or `classDef` statement, or
  an `%%{init}%%` directive, in a Mermaid block. Use a
  [colour name](#diagram-colours).
- **Unknown colour names:** `class A <name>` or `A:::<name>` with a name
  not in the table above.

It runs before every `make pdf`, in the pre-commit hook whenever guide
source is staged, and in CI through `make pdf-check`.

## Links between chapters

Link to another chapter by its file, `[Heuristics](./02-heuristics.md)`, or
to a section in it, `[…](./03-part-1-foundations.md#3-the-four-primitives)`.
The pipeline turns these into links inside the PDF.
